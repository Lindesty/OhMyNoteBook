# 模块05：生产者-消费者集合

## 概述

本模块介绍C#中的生产者-消费者集合，包括 `ConcurrentQueue`、`ConcurrentStack` 和 `ConcurrentBag`，以及它们共同实现的 `IProducerConsumerCollection` 接口。

在并发编程中，队列和栈的概念你可能已经很熟悉，但并发环境带来了一个棘手的问题：如何确保从集合中取出所有项目？在单线程环境中，当队列为空时就意味着处理完成；但在多线程环境中，即使队列暂时为空，其他线程可能仍会添加新项目。这是本模块的核心关注点。

本模块继续使用 Geek Clothing Company 的买卖示例应用来演示这些概念。在原有基础上，我们添加了日志功能：每次交易后，交易详情会被记录到中央数据存储。由于日志处理较慢（可能是数据库连接慢等原因），我们不希望销售线程被阻塞。解决方案是使用一个交易队列，销售线程立即将交易信息入队，然后由专门的日志线程异步处理。

## 核心概念

### 1. 生产者-消费者模式

在生产者-消费者模式中：
- **生产者线程**：生成需要处理的项目（本例中是待记录的交易）
- **消费者线程**：从集合中取出项目进行处理（本例中是日志记录线程）

```
销售线程1 --\
销售线程2 --+--> [交易队列] --> 日志线程1
销售线程3 --/                    日志线程2
```

### 2. ConcurrentQueue - 并发队列

`ConcurrentQueue` 是线程安全的先进先出（FIFO）集合。

#### 关键方法

| 方法 | 说明 |
|------|------|
| `Enqueue(T item)` | 入队操作，始终成功 |
| `TryDequeue(out T result)` | 尝试出队，返回是否成功 |
| `TryPeek(out T result)` | 查看队首元素但不移除 |

#### 代码示例：日志队列实现

```csharp
public class LogTradesQueue
{
    private ConcurrentQueue<Trade> _tradesToLog = new ConcurrentQueue<Trade>();
    private readonly StaffRecords _staffLogs;
    private bool _workingDayComplete;

    public LogTradesQueue(StaffRecords staffLogs)
    {
        _staffLogs = staffLogs;
    }

    // 生产者调用此方法添加交易
    public void QueueTradeForLogging(Trade trade) => _tradesToLog.Enqueue(trade);

    // 通知没有更多交易会到来
    public void SetNoMoreTrades() => _workingDayComplete = true;

    // 消费者线程执行此方法处理队列
    public void MonitorAndLogTrades()
    {
        while (true)
        {
            Trade nextTrade;
            bool done = _tradesToLog.TryDequeue(out nextTrade);
            
            if (done)
            {
                _staffLogs.LogTrade(nextTrade);
                Console.WriteLine($"Processing transaction from {nextTrade.Person.Name}");
            }
            else if (_workingDayComplete)
            {
                Console.WriteLine("No more sales to log - exiting");
                return;
            }
            else
            {
                // 队列为空但工作日未结束，需要等待
                Console.WriteLine("No transactions available");
                Thread.Sleep(500);
            }
        }
    }
}
```

### 3. 轮询问题

上述代码展示了一个常见问题：**轮询（Polling）**。当队列为空但工作日尚未结束时，消费者线程不知道何时会有新交易到来，只能不断检查队列。这带来两个问题：

1. **效率低下**：线程在空转，浪费CPU资源
2. **等待时间难以确定**：500毫秒是随意选择的，可能太长（响应慢）或太短（CPU浪费）

> **注意**：轮询通常被视为不良实践。下一模块将介绍 `BlockingCollection` 作为更好的解决方案。

### 4. ConcurrentStack - 并发栈

`ConcurrentStack` 是线程安全的后进先出（LIFO）集合。

#### 方法对比

| 操作 | Queue | Stack |
|------|-------|-------|
| 添加 | Enqueue | Push |
| 取出 | TryDequeue | TryPop |

#### 代码示例：从队列改为栈

```csharp
// 原来使用 ConcurrentQueue
private ConcurrentQueue<Trade> _tradesToLog = new ConcurrentQueue<Trade>();
public void QueueTradeForLogging(Trade trade) => _tradesToLog.Enqueue(trade);
bool done = _tradesToLog.TryDequeue(out nextTrade);

// 改为使用 ConcurrentStack
private ConcurrentStack<Trade> _tradesToLog = new ConcurrentStack<Trade>();
public void QueueTradeForLogging(Trade trade) => _tradesToLog.Push(trade);
bool done = _tradesToLog.TryPop(out nextTrade);
```

对于日志记录场景，处理顺序并不重要，使用队列或栈结果相同。

### 5. ConcurrentBag - 并发包

`ConcurrentBag` 是线程安全的无序集合，适用于不关心元素顺序的场景。

#### 特点

- **无序**：不保证任何特定的取出顺序
- **高性能**：当同一线程既添加又取出元素时性能最佳
- **内部机制**：尽可能为每个线程维护独立集合，减少线程同步

#### 方法

| 方法 | 说明 |
|------|------|
| `Add(T item)` | 添加元素 |
| `TryTake(out T result)` | 尝试取出元素 |

#### 重要限制

`ConcurrentBag` 在以下情况下性能最佳：
- 同一线程既生产又消费元素

而在本示例中：
- 销售线程只添加交易（生产者）
- 日志线程只取出交易（消费者）

这是完全不同的线程进行添加和移除，正好是 `ConcurrentBag` 设计的反面场景，因此不是最佳选择。

```csharp
private ConcurrentBag<Trade> _tradesToLog = new ConcurrentBag<Trade>();
public void QueueTradeForLogging(Trade trade) => _tradesToLog.Add(trade);
bool done = _tradesToLog.TryTake(out nextTrade);
```

### 6. IProducerConsumerCollection 接口

三种集合使用不同的方法名称，这导致代码互换性差：

| 集合类型 | 添加方法 | 取出方法 |
|---------|---------|---------|
| ConcurrentQueue | Enqueue | TryDequeue |
| ConcurrentStack | Push | TryPop |
| ConcurrentBag | Add | TryTake |

`IProducerConsumerCollection` 接口解决了这个问题，它统一了方法命名：

```csharp
public interface IProducerConsumerCollection<T> : IEnumerable<T>, ICollection
{
    void CopyTo(T[] array, int index);
    T[] ToArray();
    bool TryAdd(T item);    // 统一的添加方法
    bool TryTake(out T item); // 统一的取出方法
}
```

#### 使用接口实现代码互换性

```csharp
public class LogTradesQueue
{
    // 使用接口声明，可以轻松切换具体实现
    private IProducerConsumerCollection<Trade> _tradesToLog 
        = new ConcurrentQueue<Trade>();
    // 也可以是:
    // = new ConcurrentStack<Trade>();
    // = new ConcurrentBag<Trade>();

    public void QueueTradeForLogging(Trade trade) => _tradesToLog.TryAdd(trade);

    public void MonitorAndLogTrades()
    {
        while (true)
        {
            Trade nextTrade;
            bool done = _tradesToLog.TryTake(out nextTrade);
            // ... 其余逻辑相同
        }
    }
}
```

#### 为什么使用 TryAdd？

虽然 `Queue`、`Stack` 和 `Bag` 的添加操作永不失败，但接口使用 `TryAdd` 是为了面向未来扩展。例如，可能有人会实现一个有容量限制的队列，添加可能失败。

> **注意**：`ConcurrentQueue` 和 `ConcurrentStack` 显式实现了 `TryAdd` 和 `TryTake`，这些方法只能通过接口引用访问。

## 完整示例：交易日志系统

### 交易实体类

```csharp
public enum TradeType { Sale, Purchase }

public class Trade
{
    public SalesPerson Person { get; private set; }
    public TShirt Shirt { get; private set; }
    public int Quantity { get; private set; }
    public TradeType Type { get; private set; }
    public bool IsSale => Type == TradeType.Sale;

    public Trade(SalesPerson person, TShirt shirt, TradeType type, int quantitySold)
    {
        this.Person = person;
        this.Shirt = shirt;
        this.Type = type;
        this.Quantity = quantitySold;
    }
}
```

### 员工记录类（计算佣金）

```csharp
public class StaffRecords
{
    private ConcurrentDictionary<SalesPerson, int> _commissions 
        = new ConcurrentDictionary<SalesPerson, int>();

    public void LogTrade(Trade trade)
    {
        Thread.Sleep(30); // 模拟慢速操作
        if (trade.IsSale)
        {
            int tradeValue = trade.Shirt.PricePence * trade.Quantity;
            int commission = tradeValue / 100; // 1% 佣金
            _commissions.AddOrUpdate(
                trade.Person, commission, 
                (key, oldValue) => oldValue + commission);
        }
    }

    public void DisplayCommissions(IEnumerable<SalesPerson> people)
    {
        Console.WriteLine("\nBonus by salesperson:");
        foreach (SalesPerson person in people)
        {
            int bonus = _commissions.GetOrAdd(person, 0);
            Console.WriteLine($"{person.Name,15} earned ${bonus / 100}.{bonus % 100:00}");
        }
    }
}
```

### 主程序

```csharp
static void Main(string[] args)
{
    StockController controller = new StockController();
    TimeSpan workDay = new TimeSpan(0, 0, 0, 0, 500);
    StaffRecords staffLogs = new StaffRecords();
    LogTradesQueue tradesQueue = new LogTradesQueue(staffLogs);

    // 创建销售人员
    SalesPerson[] staff = {
        new SalesPerson("Sahil"),
        new SalesPerson("Julie"),
        new SalesPerson("Kim"),
        new SalesPerson("Chuck")
    };

    // 启动销售任务（生产者）
    List<Task> salesTasks = new List<Task>();
    foreach (SalesPerson person in staff)
    {
        salesTasks.Add(
            Task.Run(() => person.Work(workDay, controller, tradesQueue)));
    }

    // 启动日志任务（消费者）
    Task[] loggingTasks = {
        Task.Run(() => tradesQueue.MonitorAndLogTrades()),
        Task.Run(() => tradesQueue.MonitorAndLogTrades())
    };

    // 等待工作日结束
    Task.WaitAll(salesTasks.ToArray());
    
    // 通知没有更多交易
    tradesQueue.SetNoMoreTrades();
    
    // 等待日志完成
    Task.WaitAll(loggingTasks);

    // 显示结果
    controller.DisplayStock();
    staffLogs.DisplayCommissions(staff);
}
```

## 要点总结

### 三种生产者-消费者集合对比

| 特性 | ConcurrentQueue | ConcurrentStack | ConcurrentBag |
|------|-----------------|-----------------|----------------|
| 顺序 | FIFO（先进先出）| LIFO（后进先出）| 无序 |
| 添加方法 | Enqueue | Push | Add |
| 取出方法 | TryDequeue | TryPop | TryTake |
| 最佳场景 | 顺序处理要求 | 后进先出需求 | 同线程生产消费 |

### 核心要点

1. **生产者-消费者模式**：多个线程生产项目，其他线程消费项目的经典并发模式。

2. **入队 vs 出队的不对称性**：
   - 入队/添加操作始终成功，不需要 `Try` 前缀
   - 出队/取出操作可能失败，需要 `Try` 前缀

3. **空队列的处理困境**：
   - 单线程：队列为空 = 处理完成
   - 多线程：队列为空 ≠ 处理完成（可能有新项目即将到来）
   - 简单解决方案是轮询，但效率不高

4. **IProducerConsumerCollection 接口**：
   - 统一了三种集合的方法命名（`TryAdd`/`TryTake`）
   - 提供代码互换性
   - `TryAdd` 为未来可能的有限容量集合预留设计

5. **ConcurrentBag 的性能特点**：
   - 适合同一线程既添加又取出的场景
   - 不适合独立的生产者和消费者线程

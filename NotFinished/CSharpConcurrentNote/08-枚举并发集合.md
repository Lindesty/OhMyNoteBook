# 08 - 枚举并发集合

## 概述

本模块是C#并发集合课程的最后一个模块，主要讨论如何在并发环境中枚举集合。在并发环境下枚举集合面临一个核心问题：当集合正在被枚举时，其他线程可能会修改该集合。我们需要了解如何正确处理这种情况。

本模块将介绍两种可能的解决方案：
1. 直接枚举，允许在枚举过程中进行修改
2. 通过快照（Snapshot）来枚举集合，避免修改带来的问题

## 核心概念

### 1. 标准集合的枚举行为

在了解并发集合之前，我们先看看标准集合（如 `Dictionary<TKey, TValue>`）的枚举行为。

标准集合在枚举时有一个隐含的期望：**集合在枚举期间不应被修改**。如果检测到修改，枚举器会抛出异常。

```csharp
// 示例：标准字典枚举时修改会抛出异常
var stock = new Dictionary<string, int>();
stock.Add("kcdc", 0);
stock.Add("Pluralsight Live 2018", 0);
stock.Add("docker", 0);

foreach (var shirt in stock)
{
    // 在枚举过程中修改集合
    stock["kcdc"] += 1;  // 会抛出异常！
    Console.WriteLine(shirt.Key + ": " + shirt.Value);
}
```

运行上述代码会抛出异常：
```
Collection was modified; enumeration operation may not execute.
```

这表明标准字典的枚举器非常智能——它能够检测到字典被修改，并拒绝继续枚举。在单线程环境中，这是合理的行为。

### 2. 并发字典的枚举行为

在多线程环境中，枚举器无法阻止其他线程修改集合，因此并发集合必须采取更宽松的方式。

`ConcurrentDictionary<TKey, TValue>` 提供了两种枚举方式：

#### 方式一：直接枚举（可能看到不一致的结果）

```csharp
var stock = new ConcurrentDictionary<string, int>();
stock.TryAdd("kcdc", 0);
stock.TryAdd("Pluralsight Live 2018", 0);
stock.TryAdd("docker", 0);

foreach (var shirt in stock)
{
    stock["kcdc"] += 1;
    Console.WriteLine(shirt.Key + ": " + shirt.Value);
}
```

**直接枚举的特点：**
- 枚举会成功执行，不会抛出异常
- 结果**不可预测**：枚举器会在到达每个元素时获取其当前状态
- 如果在枚举期间修改了元素，枚举器看到的值取决于时序——它可能在修改之前或之后获取该元素
- 如果添加或删除元素，枚举器甚至不能保证会看到这些元素
- 枚举顺序可能与添加顺序无关

**注意：** 这种方式效率高，但结果可能每次运行都不同。

#### 方式二：快照枚举（结果一致）

通过调用 `ToArray()` 方法，可以在枚举开始时获取集合的快照：

```csharp
var stock = new ConcurrentDictionary<string, int>();
stock.TryAdd("kcdc", 0);
stock.TryAdd("Pluralsight Live 2018", 0);
stock.TryAdd("docker", 0);

// 使用 ToArray() 获取快照
foreach (var shirt in stock.ToArray())
{
    stock["kcdc"] += 1;  // 修改原集合不影响快照
    Console.WriteLine(shirt.Key + ": " + shirt.Value);
}
```

**快照枚举的特点：**
- 枚举的是快照，而非原始集合
- 结果代表集合在某一时刻的**一致性状态**
- 枚举期间对原集合的修改不会影响枚举结果
- `Keys` 和 `Values` 属性也会返回快照

### 3. 其他并发集合的枚举行为

`ConcurrentStack<T>`、`ConcurrentQueue<T>` 和 `ConcurrentBag<T>` 的枚举行为与 `ConcurrentDictionary` 不同：

- 这些集合在枚举时**总是使用快照**
- 不提供直接枚举的选项

这与之前课程中提到的 `BlockingCollection` 封装队列时的行为一致——直接枚举不会获取后续添加的元素，因为枚举的是快照。

### 4. 快照的优缺点

| 方面 | 快照枚举 | 直接枚举 |
|------|----------|----------|
| **优点** | 结果一致、可预测 | 性能高、效率好 |
| **缺点** | 需要复制整个集合，开销大 | 结果不可预测、可能不一致 |
| **适用场景** | 需要一致性结果时 | 对结果一致性要求不高、性能敏感时 |

**重要提醒：** `ConcurrentDictionary` 的 `Keys` 和 `Values` 属性会返回快照，调用开销较大。应避免频繁调用这些属性。

### 5. 课程总结

本课程的核心要点：

1. **使用并发集合**：当多个线程需要读写同一集合时，应使用并发集合提供线程安全访问
2. **不可变集合**：如果集合内容固定不变，考虑使用不可变集合
3. **不仅仅是替换**：不要简单地将标准集合替换为并发集合——仍需确保程序逻辑在并发环境中正确工作
4. **避免竞态条件**：并发集合本身不保护你免受竞态条件的影响
5. **善用便捷方法**：`GetOrAdd` 和 `AddOrUpdate` 是避免竞态条件的有力工具
6. **设计时考虑**：获取集合的精确状态往往困难或代价高昂，尽量设计逻辑以避免这种需求

## 最终挑战

### 问题描述

在本课程的买卖示例中，`BuyStock` 方法使用了 `AddOrUpdate` 方法来解决并发问题。挑战是：**假设 `AddOrUpdate` 方法不存在，如何使用 `TryUpdate` 等低级方法实现相同功能？**

### 挑战规则

- 可以使用任何 `TryXXX` 低级方法（`TryGetValue`、`TryAdd`、`TryUpdate` 等）
- **禁止**使用高级方法 `GetOrAdd` 和 `AddOrUpdate`
- **禁止**使用锁或其他显式线程同步工具

### 原始代码（使用 AddOrUpdate）

```csharp
public void BuyStock(string code, int quantity)
{
    _stock.AddOrUpdate(code, quantity, (key, oldValue) => oldValue + quantity);
    Interlocked.Add(ref _totalQuantityBought, quantity);
}
```

### 解决方案

```csharp
public void BuyStock(string code, int quantity)
{
    // 首先确保该项存在于字典中
    _stock.TryAdd(code, 0);

    // 持续尝试更新值，直到成功为止
    // TryUpdate 只有在比较值匹配时才会成功更新
    // 如果失败（其他线程修改了值），则重试
    bool success;
    do
    {
        int oldStock = _stock[code];
        success = _stock.TryUpdate(code, oldStock + quantity, oldStock);
    } while (!success);

    Interlocked.Add(ref _totalQuantityBought, quantity);
}
```

### 解决方案解析

1. **确保存在**：首先使用 `TryAdd` 确保键存在于字典中，值为0
2. **循环更新**：使用 `do-while` 循环配合 `TryUpdate` 方法
3. **条件更新**：`TryUpdate(key, newValue, comparisonValue)` 只有当当前值等于 `comparisonValue` 时才会更新
4. **重试机制**：如果更新失败（其他线程修改了值），循环会继续尝试，直到成功
5. **性能考量**：正常情况下，循环只需迭代一到两次

**关键提示：** `TryUpdate` 方法会以线程安全的方式更新值，但存在失败风险。如果失败，没有理由不再次尝试直到成功。

## 要点总结

1. **标准集合枚举**：在枚举期间检测到修改会抛出异常
2. **并发字典枚举**：提供两种方式——直接枚举（不可预测）和快照枚举（一致）
3. **其他并发集合**：`ConcurrentStack`、`ConcurrentQueue`、`ConcurrentBag` 总是使用快照枚举
4. **快照开销**：获取快照需要复制整个集合，应避免频繁调用
5. **选择依据**：根据是否需要一致性结果和性能要求选择枚举方式
6. **低级方法替代**：可以使用 `TryUpdate` 配合循环实现 `AddOrUpdate` 的功能
